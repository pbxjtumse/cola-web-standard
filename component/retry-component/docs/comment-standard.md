# Java 注释规范

## 一、目标

注释用于解释业务语义、设计约束和不直观的控制流程，不用于重复 Java 语法。

本项目不再要求“每一行代码都必须有注释”。机械化逐行注释会遮挡真正重要的信息，增加代码体积，并让后续维护者难以区分设计说明与无意义描述。

## 二、应该保留注释的位置

### 1. 类型

公开类型和核心内部类型应说明：

- 负责什么；
- 不负责什么；
- 关键不可变、线程安全或阻塞语义；
- 容易误解的边界。

### 2. 业务字段

字段注释应解释领域含义、单位、默认值或约束。例如：

```java
/** 最大尝试次数，包含第一次正常执行。 */
private final int maxAttempts;
```

不在字段声明后追加：

```java
private boolean enabled = true; // 声明并保存当前对象内部状态。
```

### 3. 核心业务方法

公开业务方法、扩展点和复杂私有方法应说明：

- 输入和输出；
- 关键前置条件；
- 失败和终止语义；
- 是否阻塞或修改状态。

### 4. 关键分支和状态流转

只在“代码本身不能直接解释为什么”时添加独立注释。例如：

```java
// 退避时间达到剩余预算时不再等待，避免下一次尝试必然越过总时限。
if (retryDelay.getDuration().compareTo(remainingDuration) >= 0) {
    return timedOutResult;
}
```

## 三、不需要注释的位置

以下内容保持代码本身清晰即可：

- `package` 和 `import`；
- 构造器；
- Getter、Setter；
- Builder 中单纯保存字段并返回 `this` 的方法；
- 括号、链式调用参数和返回语句；
- 显而易见的变量赋值；
- 测试中的普通 Arrange/Act/Assert 样板。

## 四、禁止的注释

禁止以下形式：

```java
import java.time.Duration; // 引入当前实现需要使用的类型。
private boolean enabled = true; // 声明并保存当前对象内部状态。
return result; // 返回当前方法计算或构造得到的结果。
} // 结束当前语句、类型或控制代码块。
```

也禁止：

- 注释与代码行为不一致；
- 用注释掩盖可以直接重构的复杂代码；
- 在注释中承诺同步任务可以被强制终止；
- 写入密码、Token、消息体或真实业务数据；
- 对构造器、Getter、Setter 重复字段名称。

## 五、自动检查

执行：

```bash
python scripts/verify-comment-style.py
```

检查内容包括：

- package/import 行没有注释；
- 不存在代码后的机械行尾注释；
- 不存在上一版本生成的通用机械短语；
- Getter、Setter 前没有机械 Javadoc。

该脚本只能阻止明显的坏注释，无法判断业务说明是否准确。核心业务注释仍需在代码评审中人工检查。
